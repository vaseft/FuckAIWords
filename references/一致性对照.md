# 与原 bot 版本的一致性对照

结论先说：**同源，但不是同一个运行系统。**

- **证据层逐字节一致**：本包保存的 7 个源文件快照，SHA-256 与来源 QQ-agent 当前工作树完全相同（2026-10-25 核对）。
- **规则内核同源**：`prompts/runtime.md` 是 `prompts/anti_template.md` 的通用化重写，保留判断方式和价值取向，不保留平台特定条目。
- **执行点不同**：原 bot 是"每轮生成时注入 + 发送前检查"的在线纪律；本包是"装配一份表达层 + 离线采样校准"的可移植方案，默认不拦截任何消息。
- **反馈方式不同**：原 bot 靠人工直接改 `anti_template.md`；本包是「一百问 → 人工审核 → 回填示例 → 复测」。

所以不能宣称"和你的 bot 完全一致"。要完全复刻，需要把原工程的三层机制一起带走，见本文末「如何完全复刻」。

## 二、逐层对照

| 层 | 原 bot 实际做法 | 本包做法 | 是否等价 |
| --- | --- | --- | --- |
| 生成层 | `anti_template.md` 19 条偏好直接注入系统提示，与 `character.md`、`conversation.md` 并列 | `prompts/runtime.md` 7 段原则；平台与角色条目改为可迁移的判断方式 | **不完全等价**，原则保留，具体禁令减少 |
| 词面层 | `natural-dialogue` 插件 `check()` 产出 22 类 flag，`before-send` 钩子在 `assist` 模式下可删除 6 类句式 | `runtime/quality.mjs` 零依赖观察器，默认 `observe`，只返回 `WARN` 与疑点，不改消息 | **不等价**，只保留观察能力 |
| 发送层 | `send-guard.reviewOutgoing()` 统一审查：附件失败说明静默、`explicitRequest` 复核压制、`validRevision` 只允许变短 | 无发送链路，装配后由目标自己发送与审查 | **不等价**，依赖目标原有发送逻辑 |
| 语义层 | `expression-memory` 记录成功发送的表达特征，同语境 bigram 近似判 `SEMANTIC_REPEAT`，只记录不拦 | 保留设计说明与来源快照；本包未实现跨日持久化 | **不等价**，需目标具备历史存储 |
| 反馈层 | 人工直接改 `anti_template.md`，线上即时生效 | 一百问采样 → 人工审核 → 编译示例 → 标记块回填 → 复测 | **不等价**，从"改规则"变为"示例化校准" |

## 三、原 bot 的三条安全不变量（本包只保留为设计原则）

1. **只缩短，不新增**：`validRevision()` 要求改写结果条数不增、总字数不增、每项非空。防止"修复 AI 味"时塞进新事实。
2. **明确请求优先**：私聊、被 `@`、正文点名时，压制不生效。防止为了"不像客服"而不回答正当问题。
3. **质检失败放行**：`QUALITY_CHECK_ERROR` 只告警不阻断。防止风格检查把聊天整体拖死。

本包把这三点写进 `AGENT.md` 与装配约束，但**没有代码级强制**——因为改的是别人的提示词，不是自己控制的发送链路。需要强制时，得由目标项目在自己的发送路径上实现。

## 四、没有迁移的原文条目

以下条目在 `anti_template.md` 里存在，但本包不设为跨场景默认。原文证据保留在 `evidence/source/prompts/anti_template.md`。

| 原文条目 | 未迁移原因 | 本包的处理 |
| --- | --- | --- |
| 被骂废物/垃圾时必须用脏话还击 | 特定角色与社群偏好，不是通用语言规律 | 允许有态度，不强制辱骂（`mandatory_swearing: false`） |
| 被叫复读机就原样重复最后一句 | 依赖群聊上下文与熟人关系 | 保留为可选场景示例，不做默认 |
| 被叫宠物时先声明"我是虚拟 AI" | 与"不要每句重申身份"存在张力 | 合并为"玩笑不改变能力事实" |
| 破折号、省略号、分号一律不用 | 技术文本与引用中可能必要 | 降为闲聊偏好，技术语境豁免 |
| 群文件功能不确定时先问手机还是电脑 | 平台特定 | 未迁移 |
| 群聊要代码只给十行内 | 与真实排错需求冲突 | 改为"长度随事情走" |
| 管理员身份与恶意诱导判定 | 平台权限结构特定 | 只保留"可信来源与参与边界"原则 |
| 固定起手"行"必须换 | 属于可确定检查的词面问题，不该占生成注意力 | 保留在词面观察器里，不做生成层禁令 |

这些取舍的完整理由见 [来源与取舍](来源与取舍.md)。

## 五、如何完全复刻原 bot

需要三样东西同时到位，缺一不可：

1. **生成层原文**：把 `evidence/source/prompts/` 下三份原文按原顺序注入，而不是只装 `runtime.md`。
2. **词面层**：把 `evidence/source/natural-dialogue.mjs` 接进目标的发送前钩子，并按原 `plugin.json` 配置 `mode: "assist"`、显式 `scopes`。注意：其正则含来源项目偏好，会误报，必须先在测试通道核对。
3. **发送与记忆层**：在目标发送路径上实现 `reviewOutgoing()` 的 `explicitRequest` 复核与 `validRevision` 约束，并接上 `expression-memory` 的成功发送记录。

只装第 1 项，得到的是"表达规则相近"；三项齐全，才是"行为一致"。本包默认只做第 1 项，另外两项提供可移植的观察器与设计约束。

## 六、一致性声明的边界

- 不宣称本包与原 bot 行为等价。
- 不宣称 100 问结果代表原 bot 的生产表现；那是隔离模型测试，没有真实群聊、工具和发送链路。
- 不宣称规则在所有模型上同样有效；同一份提示在不同模型上的遵循度不同，需按模型复测。
- 原 bot 的线上效果属于原工程记录，不作为本包的实证。
