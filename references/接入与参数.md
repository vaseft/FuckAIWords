# 接入与参数

## 三层分开

`AGENT.md` 指挥加载它的 AI，既支持直接对话，也支持给其他 bot 做工程接入。`prompts/runtime.md` 只给 bot 运行时加载。`evaluation/questions.jsonl` 的 `focus` 是审核考点，不能泄露给被测 bot。

适配顺序：`probe` 确认目标与入口 → 合并一份表达规则（`install`）→ 找到最终文本发送入口 → 可选接入观察器 → 做 100 问（`collect --system-file`）→ 人审纠正 → `apply` 回填 → 复测。若平台只能给普通消息，本包仍可被读懂，但平台优先级和上下文长度会影响保持效果。

## 命令速查

| 目标 | 命令 |
| --- | --- |
| 探测本机目标 | `python scripts/deai.py probe --root <项目根>` |
| 预览写入 | `python scripts/deai.py install --target <提示文件> --dry-run` |
| 写入并导出装配后提示 | `python scripts/deai.py install --target <提示文件> --emit out/prompt.txt` |
| JSON 字段写入 | `python scripts/deai.py install --target <config.json> --mode json-path --json-path persona.roleText` |
| 回滚 | `python scripts/deai.py rollback --target <提示文件>` |
| 用装配后提示提问 | `python scripts/deai.py collect --system-file out/prompt.txt` |
| 编译并回填 | `python scripts/deai.py apply --run <runs/...> --review human-review.json --out compiled/v1 --target <提示文件>` |
| 查看阶段 | `python scripts/deai.py status` |

细节见 [装配与回填](装配与回填.md)。

不要整份替换原系统提示。权限、身份、工具调用协议、引用关系、记忆来源、媒体能力和用户明确格式要求继续由目标项目决定。旧的同职责风格段落需要合并，否则“认错只说知道了”和“必须纠正事实”等规则可能打架。

## 可选 JS 观察器

```javascript
import { QualityObserver } from './runtime/quality.mjs';
const observer = new QualityObserver({ mode: 'observe', recent_window: 8 });
const result = observer.inspect(['你准备发送的文字'], { sessionKey: '匿名会话键' });
// result.action 为 PASS 或 WARN；messages 保持原值，flags 只是疑点。
// 调用目标系统原有发送逻辑，确认送达后：
observer.confirmDelivered('匿名会话键', ['实际成功发送的文字']);
```

只有成功子集可进历史；失败、取消和被压制的草稿不进。不同会话各自维护窗口。此适配器没有文件、网络或 QQ 依赖，不修改消息，也不会因为设了 assist 就开启自动删句。故障返回 PASS，目标系统自己的安全检查不能被这个返回值绕过。

原项目的完整 `check/reviseText/hooks` 保留在 `evidence/source/natural-dialogue.mjs`。它不是本包自动启用的发送插件，不能直接假设另一平台有同名 hook。其正则包含来源项目的场景偏好，存在误报，不得把命中数当自然度评分。需启用有限修订时，由目标适配代码核对权限、目标范围、内容保真和回滚；不能只凭字数变短就认为语义没变。

## style.json 字段的实际消费者

| 字段 | 本包中怎么用 |
| --- | --- |
| `enabled` | Python 采集建提示词时校验，关闭时不生成“已加载”测试 |
| `mode` | JS 观察器支持 observe/off；不提供自动 assist 干预 |
| `recent_window` | 传入 JS 观察器后控制会话内存窗口，默认 8 |
| `maxMessagesPerHook` | 传入 JS 观察器后限制每批观察数量，未观察的消息原样保留 |
| `prompt_preferences` | Python 建立运行时以参数文本加进提示，模型偏好，不是确定性代码保证 |
| `collection` | Python 的温度、输出预算、超时、并发和瞬态重试上限 |
| `human_review` | Python 校验审核与编译时的数量、评分和示例上限；本版前端固定 100 题与 3 分门槛，若改量表需同步前端和题库校验 |
| `expression_history` | 来自原工程的持久记忆设计参数；本包未实现跨日持久化，不能宣称已启用 |
| `scopes/reviseEnabled/suppressEnabled/suppressMaxChars` | 保留原工程的适配字段，通用观察器不消费；不应误认为改 JSON 就能控制目标 bot |

运行时提示词不由宿主自动读取本配置。使用纯 Markdown 时要把所需偏好合入提示；使用 JS 时显式把对应字段传给构造函数。修改配置后新建测试运行，旧运行冻结其原有参数。

## 输出协议和测试边界

采集器借用现有项目采用的 Chat Completions 请求形状。只发送模型名、system/user/assistant 消息、温度、max_tokens 和 stream=false。额外的 reasoning 文本不落盘。平台若拒绝这些字段或需要别的协议，应做适配或 JSONL 导入，不自动猜测新协议。

为区分“没回答”和“决定不插话”，API 采集额外要求输出 `{"action":"reply","text":"..."}` 或 `{"action":"no_reply","text":""}`。封装错误单列为采集失败，不能冒充自然回复。原始封装也保存，审核只看实际 text。该封装不会进入编译后的生产表达层。

本次测试不挂真实工具，工具回执都由题目夹具提供；不验证网页搜索、QQ 取消任务、真实媒体解析或送达是否能工作。要验证生产 bot，需要在其获授权的测试通道上重跑并导入，不能把隔离测试当端到端结果。

同版本对照时锁定模型、参数、上下文和工具夹具。一次采样不能证明普遍改善。回填后再采集一轮，用新的审核文件比较，不复用旧回答哈希的审核。
