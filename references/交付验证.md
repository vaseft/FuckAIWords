# 本轮交付验证

日期：2026-10-25，用户时区 Asia/Shanghai。

## 实际采集

- 模型：本机当前配置的 `deepseek-chat`。温度 0.8，max_tokens=1400，最多四组并发；每个连续会话内部逐轮执行。
- 表达层：本包的 `prompts/runtime.md` + 冻结的参数偏好 + 区分发言/沉默的离线 JSON 封装；每题审核考点未送入模型。
- 100 题全部取得有效结果，0 个最终接口错误，0 个未采集项。
- Q031 首次返回 JSON 封装末尾多一个右花括号，判为采集错误；随后仅重试该题并成功。失败原文保留在尝试记录中；其他成功题未重跑。
- Q091–Q095、Q096–Q100 分别为连续五轮，使用各会话的真实模型历史。其他题互相隔离。
- 使用合成输入与合成工具夹具，没有读取真实聊天窗口，没有执行真实工具，没有向 QQ 群发送消息。
- **100 条均待人工审核。未给自然度、贴合度或正确性打分；没有人工通过的修正产物，没有宣称效果已提升。**

## 工程验证

`python scripts/test_workflow.py`：22 个隔离测试通过，使用临时目录和模拟接口，不进入本轮真实结果。覆盖：

- 一百题编号与分层，以及审核考点不进入模型输入。
- 改提示词、参数或原始回答会使证据校验失败。
- 缺人工签认、错误回答哈希、低分、待审和拒绝状态不能生成正式验收版。
- 局部编译标为未验收；纠正成沉默有效，空白发言无效。
- 错误结果不能人工通过；导入不覆盖成功记录，整批导入先校验再落盘。
- 断点恢复不重复请求成功题，连续题接续真实历史，前一题失败则后续暂停。
- 测试连接密钥没有写入运行文件。

`node scripts/test_observer.mjs`：原消息不改变、检查预算不丢尾部、只有确认送达后才记忆、会话隔离和关闭语义通过。这个测试不证明原正则没有误报。

## 探测、装配与回填的验证

本轮新增 `scripts/probe.py` 与 `deai.py` 的 `probe / install / rollback / apply / status`，并给 `collect` 增加 `--system-file`。实际测试覆盖：

- **探测**：在本机真实目录中命中 QQ-agent 项目，给出 `json-path → persona.roleText` 与 `chat-completions` 建议；排除 `napcat` 协议端子目录；不把普通 `src/`、测试数据目录当成独立项目。
- **密钥零泄露**：目标配置里的 `apiKey` 和环境变量里的 `DEAI_API_KEY` 均不出现在 survey JSON 或标准输出中，只保留 `present / has_key`。测试用假密钥 `sk-…` 断言其不出现。
- **装配幂等**：同一表达层重复写入返回 `changed=false`；换版本后目标文件仍只有一个 `deai:begin` 块，原内容保留。
- **dry-run**：不写目标文件，不生成 `install-state.json`。
- **回滚**：`rollback` 后目标文件与写入前逐字节一致。
- **JSON 字段模式**：只改 `persona.roleText`，`api.model` 等其它字段原样保留；字段缺失或缺 `--json-path` 时直接报错。
- **拒绝条件**：`.js` 目标、本包 `prompts/` 目录、含 `sk-` 的表达层都拒绝写入。
- **回填端到端**：`apply` 先编译 100 条人工通过样本（合成夹具），再写入临时目标；`release_ready=true`、标记块唯一、备份存在。
- **状态机**：`status` 的 `human-review` 恒为未完成，并明确写“人工审核结论不由程序推断”。
- **整包提问**：`new_run(source=...)` 把 `--system-file` 记入 manifest 的 `system_source`，采集使用装配后的完整提示。

未验证部分：没有对真实第三方 bot 做端到端装配（需要目标所有者授权并接受文件改动）；`probe` 的端口识别在未运行本地模型服务时只能验证文件类候选；`install` 的 `copy-skill-dir` 是人工复制动作，由宿主决定是否加载。上述测试不产生任何人工审核结论。

离线页面 DOM 测试：使用来源工程已有 jsdom，在一次性内存浏览器中检查 100 张卡片、默认全部待审、搜索、原句保留、修改和导出、签认门槛、本地草稿、错误运行拒绝、0 个 JavaScript 错误。测试中的签认是明确标记的模拟夹具，没有导出为用户结果，也没有写入实际浏览器审核状态。

技能元数据校验使用 skill-creator 的 quick_validate.py。其 PyYAML 依赖只安装到系统临时目录；本包采集和编译仍仅依赖 Python 标准库。

## 视觉与适配范围

尝试通过 Tabbit 打开页面时，浏览器运行服务拒绝新建页面；获取可见空白页也失败。该任务已正常结束，没有修改用户现有网页。页面尚未取得实际浏览器截图，不把 DOM 测试写成视觉验收。

此包支持纯文本读取、文件读取、兼容 API 采集及外部 bot 输出导入。未对每家模型和每个平台做适配验证；未验证生产 QQ 的完整角色、权限、语音、媒体、真实工具、回执或性能。没有跨平台“自动装载任何 AI”的承诺。

ZIP 的 CRC、静态源文件哈希、冻结题库和回答哈希由打包与 verify 命令校验。迁移验证在临时目录解压后执行，确认不需要来源项目路径。人工审核状态由操作者签认决定，自动测试和哈希不会产生人工通过结论。
