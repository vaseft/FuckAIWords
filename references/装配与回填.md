# 装配与回填

本文件只讲“怎么把表达层安全地写进目标，再把人工纠正写回去”。玩法边界见 `AGENT.md`，接口与参数见 `接入与参数.md`。

## 零、人设优先

装配不是重写角色。目标已有的性格、世界观、人物关系、口癖、能力边界、权限、禁区，全部原样保留；本包只在末尾追加表达偏好，冲突时以目标为准。

- `marker` 与 `json-path` 都是追加：原文字符不动，只维护一个 `deai:begin … deai:end` 块。
- 安装结果里的 `preserved_original_chars` 是原内容保留的字符数，`persona_policy` 应为 `preserve-existing`。
- `replace` 会丢弃原有设定，结果标为 `replace-all` 并带 `warning`；只有用户明确说“不用管原设定”时才可用。
- 本包某条与目标人设冲突（例如目标是冷淡话少，某条示例偏热情）时，跳过该条，不要改目标。

## 一、先探测，再决定装配方式

```sh
python scripts/deai.py probe --root <目标项目根>
```

`survey.json` 里每个候选带 `install.method`：

| method | 含义 | 目标形态 |
| --- | --- | --- |
| `marker` | 在文本提示词中维护标记块 | `.md` / `.txt` |
| `json-path` | 只改 JSON 里的某个字符串字段 | `config.json` 的 `persona.roleText` 等 |
| `copy-skill-dir` | 把本包复制成 `<skills>/deai-dialogue` | skill 目录 |
| `replace` | 整份替换 | 仅用户明确要求时 |

`copy-skill-dir` 是手工动作：把整个目录复制过去即可，不需要 `install`。`deai-dialogue/SKILL.md` 会作为入口被宿主加载。

## 二、四种写入模式

### 先选位置：`--position end|start`

位置与写入模式正交，marker 和 json-path 都生效。它决定表达层落在目标文本的末尾还是开头，直接影响缓存能否覆盖这约 700 字。

| 值 | 含义 | 什么时候用 |
| --- | --- | --- |
| `end`（默认） | 追加在原文之后 | 目标是人设字段，记忆由宿主在文件外拼接 |
| `start` | 插在原文之前 | 目标是一整份系统提示，中间会插入记忆、时间、群信息 |

```sh
python scripts/deai.py cache-plan --target "data/config.json" --json-path persona.roleText
```

`cache-plan` 输出两种位置的 `cached_prefix_chars`、`gain_chars`、`gain_level` 和 `recommend`。它只读目标文件本身：文件里没有 `{memory}` 这类占位符时，会返回 `gain_level=none`，意思是两种位置缓存覆盖相同（因为表达式层无论放哪都在宿主的动态内容之前），此时默认 end。

位置可以来回切，脚本会把已有标记块搬到新位置，不会留两份。

### marker（默认，文本提示词）

```sh
python scripts/deai.py install --target "path/to/system.md" --dry-run
python scripts/deai.py install --target "path/to/system.md" --label v1
# 缓存优先：加 --position start
```

写入后的形状：

```markdown
（目标原有内容，完全保留）

<!-- deai:begin label=v1 sha256=6f3fa0c691e5 -->
（表达层正文）
<!-- deai:end -->
```

- 已有标记块时**替换**，不会越写越多；指定了不同的 `--position` 时会搬到新位置。
- 没有标记块时，按 `--position` 放到开头或末尾。
- `sha256` 是表达层正文的摘要，用来判断文件里的版本和新版本是否一致。

### json-path（配置字段）

```sh
python scripts/deai.py install --target "data/config.json" --mode json-path --json-path persona.roleText
```

- 只把标记块追加到该字段字符串内部，`roleText` 原有内容保留在前。
- 文件其余字段、顺序和值不变；缩进按原文件探测（2 / 4 / Tab）。
- 字段不存在或不是字符串时直接报错，不猜结构。
- `.jsonc` 带注释时解析会失败，应改用文本方式或人工合并。

### append / replace

- `append`：无条件在末尾追加一段，不做去重；只在目标不能被标记块管理时使用。
- `replace`：整份替换，必须 `--force`。**会丢掉目标原有全部设定**，返回值带 `persona_policy: replace-all` 与 `warning`；除非用户明确要求，否则不要用。

### copy-skill-dir（skill 宿主）

```sh
# 示例：NewMax / Claude Code / Codex
cp -r . ~/.newmax/skills/deai-dialogue
```

复制后由宿主加载 `SKILL.md`；不要同时再往同一目标注入 marker 块，避免两份表达层重复。

## 三、备份、回滚与状态

- 每次真正写入前，原文件复制到 `backups/<文件名>.<时间戳>.bak`。
- 写入记录保存在 `install-state.json`（含目标路径、模式、标签、备份路径、表达层哈希）。
- 回滚：

```sh
python scripts/deai.py rollback --target "path/to/system.md"
python scripts/deai.py rollback          # 回滚最近一条
```

- `backups/`、`install-state.json`、`probe/` 都在 `.gitignore` 里，因为含本机绝对路径。
- `--dry-run` 只计算不落盘，适合先给用户看影响范围。

## 四、`--emit` 与“向装了 skill 的 bot 提问”

```sh
python scripts/deai.py install --target "data/config.json" --mode json-path --json-path persona.roleText --emit "out/target-prompt.txt"
python scripts/deai.py collect --system-file "out/target-prompt.txt"
```

`--emit` 导出的是**装配后的完整字段内容**：

- 文本模式：整个目标文件的当前内容。
- JSON 模式：该字段的完整字符串（原有人设 + 表达层）。

采集时用它作为系统提示，再叠加本包的输出封装（`{"action":"reply"/"no_reply"}`），得到的就是“装了这个表达层的目标”的回答，而不是只测了一份孤立规则。

`--emit` 不加 `--dry-run` 时导出的是写入后的内容；加 `--dry-run` 时导出的是预计内容，可用于预览。

## 五、回填

```sh
python scripts/deai.py apply \
  --run "runs/<你自己的运行目录>" \
  --review "human-review.json" \
  --out "compiled/v1" \
  --target "data/config.json" \
  --mode json-path --json-path persona.roleText
```

`apply` = `compile` + `install`：

1. 校验审核文件：run_id、题库哈希、提示词哈希、每条回答哈希、审核人、人工签认、评分门槛。
2. 只吸收 `pass` 与 `correct`；`reject`、`pending`、采集失败不进入。
3. 生成 `compiled/v1/runtime.md`、`approved-examples.jsonl`、`corrections.jsonl`、`report.json`。
4. 把 `runtime.md` 按同样的 marker / json-path 规则写回目标，自动备份。

`--partial` 只用于分批工作，产物是未验收草稿，`release_ready=false`。

## 六、安全与拒绝条件

脚本在以下情况直接报错，不做“尽力而为”：

| 情况 | 原因 |
| --- | --- |
| 目标是 `.js` / `.py` / 无后缀 | 防止把表达层写进代码 |
| 目标是本包的 `scripts/`、`prompts/`、`config/` 等 | 防止污染源文件 |
| 表达层或写入结果里出现 `sk-`、`ghp_`、`github_pat_`、私钥头 | 防止把密钥写进目标提示词 |
| JSON 目标没给 `--json-path` | 避免猜字段 |
| `replace` 没给 `--force` | 避免整份覆盖 |
| 审核文件哈希不匹配 | 防止用旧审核套新回答 |

## 七、装配后要做的三件事

1. 让目标做一次真实对话，确认表达层被加载（不是只看文件里有没有文字）。
2. 用 `collect --system-file` 采集一轮，确认输出封装正常、没有把考点漏给模型。
3. 核对安装结果：`preserved_original_chars` 是否等于原人设长度、`persona_policy` 是否为 `preserve-existing`；再把目标、模式、标签、备份路径、表达层哈希记进交付说明。出问题先 `rollback`，不要手工改回去。
