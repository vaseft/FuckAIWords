# 人工审核与纠正回填

## 数据流

100 题 → 真实 bot 输出 → 不可静默改写的原始记录 → 人逐条决定与改写 → 导出签认 JSON → 校验绑定信息 → 场景修正与提示示例 → 目标 bot 复测。

AI 可以出题、采集、指出疑点、给出候选改写；候选必须标为 AI 建议。本包不生成伪造的人工通过记录。勾选签认和填写审核人是操作者的声明，程序无法证明屏幕后一定是本人，哈希也不是身份认证或防篡改签名。

## 如何判一句话

先隐藏审核考点，读输入、实际历史和可信夹具。分别评自然度、贴合度、正确性，1–5 分；评分对象是最终保留的句子。若原句不好而修正版好，给修正版评分，在原因中写明原句的问题。

- 原句通过：保留精确原句和原行为。
- 人工纠正：写最终认可的句子；不能照搬 AI 建议后称“AI 已代人审核”。若应该沉默，选择保持沉默，修正文为空。
- 拒绝：这条暂时没有可接受的修正版，写具体原因。不会编入示例，整轮也不能算通过。
- 待审：没有完成人工判断，保留空评分。

三个维度都达到 3 分才可接受，不能用“自然”抵消事实错误。对孤立的“行”不必机械扣分；认真技术问题需要列表时可以列表。对同一事实再次询问，重复答案合理。特别留意 Q015、Q026、Q039、Q048、Q049、Q050：这些题用于检查风格规则有没有伤到真正的需求。

## 纠正范围

修改“我认，后面我会全面优化……”为“知道了”，适用于用户只反馈口吻问题；不能扩展到算错数时也不更正。删除无意义结尾反问适用于话已说完；不能扩展到缺少必要参数时不许澄清。`scope` 就用来记录这些条件。

审核页在原句旁提供编辑区，本地自动保存草稿，导出为正式 JSON。版本、运行 id、题库哈希、提示词哈希和各原始回答哈希必须匹配。恢复采集改变某条错误记录后，旧审核中该条的哈希将失效；不要手改哈希，应基于新页面重新确认。

审核页固定服务本包一百题。纯聊天环境没有脚本时，可按相同字段记录，但必须由人填写决定和修正版，不得把“AI 建议”当作签认。

## 外部 bot 的导入格式

先 `python scripts/deai.py init` 建立运行，按同一题库向已经加载本包规则的 bot 获取真实回答。写成每行一个 JSON，例如：

```json
{"id":"Q001","source":"actual_bot","action":"reply","answer":"在。","raw_response":"在。","collected_at":"2026-10-25T14:00:00+08:00"}
```

这里是格式演示，不是本轮 bot 的实测或人工结论。`raw_response` 必须是真实返回，不能自行代写。外部 bot 无 JSON 封装时它就等于原文；有封装时同时保留原始封装和实际文字。

不发言时明确标 `action=no_reply`、`answer=""`、`raw_response` 为目标通道实际记录的原始结果，不能把超时或网络故障算沉默。连续题第二轮及以后，额外提供 `history` 数组，使用本轮实际传入的 user/assistant 历史，不能仅靠固定参考答案拼接。

```powershell
python scripts/deai.py import --run "runs/你的运行" --file "实际回答.jsonl"
```

导入前校验所有行；不覆盖已成功的原始记录。不允许把外部导入与当前 API 的回答混成同一轮。

## 编译产物与撤回

默认 compile 要求一百题全部通过或人工纠正。`--partial` 只导出部分草稿并保留 `release_ready=false`。每次输出目录必须为空，使用 v1、v2 等新目录，避免覆盖前一版。

`approved-examples.jsonl` 保存全部已接受样本，`corrections.jsonl` 只保存修改过的样本，`human-review.json` 保存审核原件，`runtime.md` 含原有表达规则与最多 20 个跨类别纠正示例，`report.json` 保存哈希、数量和是否验收就绪。

人工签认前不生成“已通过训练集”。原 bot 回复不会自动变成人类语料；只有人认可后才成为场景示例。编译不执行部署。目标系统要回滚时替换回上一版表达提示，清理仅属于新版的表达缓存，再跑目标系统原有检查；不删原始评测证据。
